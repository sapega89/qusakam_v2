## What was built

### B82: a loaded save puts the hero back where he saved
- **Reproduced first.** `verify_save_load_room` [1]/[2] does this: the real `SavePoint._on_interacted()` on `SavePoint_BeforeCity` (it places the hero and opens `SaveGameState`), then `Game.save_game()` (the save screen's handler), then a walk to another room (Canyon), then a load the way `LoadGameMenu._load_slot()` does it (`save_file_path` + `start_new_game=false` metas, then a fresh `Game.tscn`).
  With the placement line reverted, the run FAILS: `hero is back at the save point ((368.0, 248.0), saved (4900.0, 359.9835))`. That is the default from `Game.tscn`. With the fix it PASSES.
- **Root-cause fix** (WIP 45b5cb62, now verified): `SampleProject/Scripts/Game.gd:242-246`. After `load_room()` of the saved room, `_initialize_save_and_room()` calls `place_player(PlayerStateManager.get_player_position())`. That is the shared `MetSysGame.place_player` from B80, and it runs before the first physics step, so room triggers see the hero at the saved spot. A new game still goes to `_position_player_at_start()` (Arrival). The wrong comment ("позиція вже відновлена через retrieve_game") is gone (`Game.gd:199`, `:238-241`, `:461`, `:605`).
- `PlayerStateManager.gd:54` `get_player_position()` returns the stored position (no `(100,549)` fallback). The initial state holds a `Vector2`.
- `PlayerDataModule.gd:32-34` writes `player_state.player_position` with no default. `:104-109` reads `{x,y}` with no defaults. A slot without a position raises `push_error` instead of silently using (100,549).
- `verify_save_load_room.gd:51-60, 66-69, 79-87` holds the repro and the checks.
- `docs/CLAUDE.md` → *Known Issues* now says B82 is fixed and describes the real flow.

## Decisions (agent call, Sapega to confirm)
- **D-new (B10):** The dialogue box has no Auto and no Skip (Figma `npc-dialog-simple 36:6`, D254). `dialogue_player_settings.tres` turns both off. The `%AutoButton`/`%SkipButton` nodes stay in `Scenes/UI/dialogue_box.tscn`, hidden, because the addon's `DQDialogueBox` (`@onready %AutoButton`) and `DQDialoguePlayer._ready()` (`get_auto_button().hide()`) require them. Deleting them would mean patching the addon. *(agent call, Sapega to confirm)*
- **D-new (B82):** Loading a save puts the hero at the exact position written at save time (the save point he used), in the saved room, through `MetSysGame.place_player`. A slot without a position is an error, not a fallback to (100,549). *(agent call, Sapega to confirm)*
