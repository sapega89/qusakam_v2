# 🔍 Діагностика перестворення гри

## Проблема

Якщо гра перестворюється (recreation), це може викликати подвійну телепортацію та інші проблеми.

## Причини перестворення гри

### 1. ❌ Виклик `change_scene_to_file()` на Game.tscn

**Причина:**
- Якщо десь в коді викликається `get_tree().change_scene_to_file("res://SampleProject/Game.tscn")`, це перестворює всю гру
- Це викликає `Game._ready()` знову, що може призвести до повторної ініціалізації

**Файли, які можуть викликати:**
- `SampleProject/Scripts/Menus/LoadGameMenu.gd` - рядок 231
- `SampleProject/Scripts/Menus/MainMenu.gd` - рядок 212
- `SampleProject/Scripts/Menus/Game/game_menu.gd` - рядок 219

**Рішення:**
- Переконатися, що `change_scene_to_file()` не викликається на Game.tscn під час переходів між кімнатами
- Використовувати `Game.load_room()` для переходів між кімнатами MetSys

### 2. ❌ MetSys `load_room()` викликається кілька разів

**Причина:**
- Якщо `load_room()` викликається кілька разів для тієї ж кімнати, це може призвести до повторного завантаження
- MetSys може емітувати `room_loaded` кілька разів

**Файли:**
- `SampleProject/Scripts/Game.gd` - `_initialize_save_and_room()` викликає `load_room()`
- `SampleProject/Scripts/Gameplay/Scenes/Canyon.gd` - `_transition_to_room()` викликає `load_room()`
- `SampleProject/Scripts/Portal.gd` - викликає `load_room()`
- `SampleProject/Scripts/Player.gd` - викликає `load_room()` при смерті

**Рішення:**
- Додати захист від повторного виклику `load_room()` для тієї ж кімнати
- Перевірити, чи не викликається `load_room()` кілька разів одночасно

### 3. ❌ `init_room()` викликається кілька разів

**Причина:**
- `init_room()` підключений до `room_loaded` через `CONNECT_DEFERRED`
- Якщо `room_loaded` емітується кілька разів, `init_room()` викликається кілька разів
- Це може призвести до повторного позиціонування гравця

**Рішення:**
- ✅ Додано захист від повторного виклику `init_room()` для тієї ж кімнати
- Додано лічильник викликів для діагностики

### 4. ❌ Сцена перестворюється через `change_scene_to_file()`

**Причина:**
- Якщо використовується `change_scene_to_file()` замість MetSys `load_room()`, це перестворює всю сцену
- Це викликає `_ready()` для всіх вузлів сцени, включаючи `Canyon._ready()`

**Рішення:**
- Використовувати MetSys `load_room()` для переходів між кімнатами
- Не використовувати `change_scene_to_file()` для переходів між MetSys кімнатами

## Діагностика

### Логування для перевірки перестворення:

```gdscript
# В Game._ready()
DebugLogger.info("Game: ✅ _ready() викликано вперше, ініціалізуємо гру", "Game")
# Або
DebugLogger.warning("Game: ⚠️ _ready() вже викликано (_bootstrapped=true), пропускаємо ініціалізацію", "Game")
DebugLogger.warning("Game: ⚠️ ЦЕ МОЖЕ БУТИ ПРИЧИНОЮ ПОДВІЙНОЇ ТЕЛЕПОРТАЦІЇ - гра перестворюється!", "Game")

# В Game.init_room()
DebugLogger.info("Game: ✅ init_room() викликано для кімнати %s (виклик #%d)" % [current_room, _init_room_call_count], "Game")
# Або
DebugLogger.warning("Game: ⚠️ init_room() вже викликано для кімнати %s (виклик #%d), пропускаємо" % [current_room, _init_room_call_count], "Game")

# В Canyon._ready()
DebugLogger.info("🏜️ Canyon: ========== _ready() ВИКЛИКАНО ==========", "Canyon")
```

### Перевірка в консолі:

1. **Якщо бачите кілька разів:**
   ```
   Game: ✅ _ready() викликано вперше, ініціалізуємо гру
   ```
   **Це означає:** Гра перестворюється кілька разів!

2. **Якщо бачите:**
   ```
   Game: ⚠️ _ready() вже викликано (_bootstrapped=true)
   Game: ⚠️ ЦЕ МОЖЕ БУТИ ПРИЧИНОЮ ПОДВІЙНОЇ ТЕЛЕПОРТАЦІЇ - гра перестворюється!
   ```
   **Це означає:** Гра перестворюється, але захист спрацював!

3. **Якщо бачите:**
   ```
   Game: ⚠️ init_room() вже викликано для кімнати Canyon.tscn (виклик #2), пропускаємо
   ```
   **Це означає:** `init_room()` викликається кілька разів для тієї ж кімнати!

4. **Якщо бачите кілька разів:**
   ```
   🏜️ Canyon: ========== _ready() ВИКЛИКАНО ==========
   ```
   **Це означає:** Сцена Canyon перестворюється кілька разів!

## Виправлення

### ✅ Вже виправлено:

1. **Захист від повторного виклику `init_room()`:**
   - Додано `_init_room_called_for_room` для відстеження останньої кімнати
   - Додано `_init_room_call_count` для лічильника викликів
   - Додано перевірку перед виконанням логіки

2. **Логування для діагностики:**
   - Додано детальне логування в `Game._ready()`
   - Додано детальне логування в `Game.init_room()`
   - Додано логування позицій гравця

3. **Позиціонування на SavePoint:**
   - Додано автоматичне позиціонування на SavePoint при поверненні до Canyon
   - Додано перевірку відстані до SavePoint перед позиціонуванням

### ⚠️ Потрібно перевірити:

1. **Чи не викликається `load_room()` кілька разів:**
   - Додати захист від повторного виклику `load_room()` для тієї ж кімнати
   - Перевірити всі місця, де викликається `load_room()`

2. **Чи не викликається `change_scene_to_file()` на Game.tscn:**
   - Перевірити всі місця, де викликається `change_scene_to_file()`
   - Переконатися, що не викликається на Game.tscn під час переходів

3. **Чи не емітується `room_loaded` кілька разів:**
   - Додати логування в MetSys для відстеження емісії `room_loaded`
   - Перевірити, чи не викликається `load_room()` кілька разів
