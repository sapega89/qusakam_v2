# 🔧 Виправлення збереження стану воріт при переходах

## Проблема

При поверненні до сцени Canyon ворота з'являлися закритими, навіть якщо вони мали бути відкритими відповідно до поточного стану гри. Це відбувалося тому, що:

1. GateControllers створювалися з `open_by_default = false` без урахування поточного прогресу
2. Ворота не перевіряли quest flags при ініціалізації
3. Стан воріт не синхронізувався з поточним прогресом гри при завантаженні сцени

## Причина

1. **Неправильна ініціалізація GateControllers**: При створенні GateControllers в `_ensure_gate_controllers()` встановлювався `open_by_default = false`, незалежно від поточного прогресу гри.

2. **Відсутність перевірки quest flags**: GateControllers не перевіряли quest flags при ініціалізації, тому ворота завжди починали як закриті.

3. **Несинхронізований стан**: Стан воріт не синхронізувався з поточним прогресом при поверненні до сцени.

## Виправлення

### 1. Покращено `_ensure_gate_controllers()`

**Файл:** `SampleProject/Scripts/Gameplay/Scenes/Canyon.gd`

- Додано перевірку quest flags перед створенням GateControllers
- Визначається правильний початковий стан воріт на основі:
  - Quest flags для конкретних воріт (`canyon_abduction_complete`, `canyon_exploration_complete`)
  - Глобального флагу `village_left_complete` (якщо гравець повернувся з Village, всі ворота відкриті)
- `open_by_default` встановлюється на основі поточного прогресу

### 2. Покращено `_check_quest_status()` в GateController

**Файл:** `SampleProject/Scripts/Gameplay/GateController.gd`

- Додано перевірку глобального флагу `village_left_complete`
- Якщо гравець повернувся з Village, всі ворота автоматично відкриваються
- Додано виклик `close_gate()` якщо квест не виконано

### 3. Додано оновлення існуючих GateControllers

- Якщо GateController вже існує, перевіряється та оновлюється його стан
- Використовується `open_gate()`/`close_gate()` для встановлення правильного стану

### 4. Покращено синхронізацію воріт

- Додано `call_deferred` для оновлення воріт після визначення стану
- Додано додаткові `await get_tree().process_frame` для гарантії готовності GateControllers

## Переваги

1. **Коректний стан воріт**: Ворота правильно відображаються відповідно до поточного прогресу
2. **Автоматична синхронізація**: GateControllers автоматично перевіряють quest flags при ініціалізації
3. **Гнучкість**: Підтримка як індивідуальних quest flags, так і глобального флагу `village_left_complete`
4. **Детальне логування**: Всі зміни стану воріт логуються для діагностики

## Перевірка

Після виправлень перевірте:

1. ✅ При поверненні з Village до Canyon всі ворота відкриті
2. ✅ Ворота правильно відображаються відповідно до поточного стану
3. ✅ Quest flags правильно впливають на стан воріт
4. ✅ Логування показує правильний стан воріт при завантаженні сцени

1. Чи встановлюються quest flags правильно

3. Чи `_check_quest_status()` викликається при ініціалізації
