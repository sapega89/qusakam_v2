# 🔧 Виправлення повторного запуску діалогів

## Проблема

При поверненні до сцени Canyon діалоги запускалися повторно, навіть якщо вони вже були прочитані. Це відбувалося тому, що:
1. Стан сцени визначався правильно (наприклад, `RELIC_PICKUP`)
2. Але діалоги все одно запускалися, бо не було перевірки на завершеність діалогів
3. Гравець змушений був повторно читати діалоги, які вже бачив

## Причина

Функції стану (`_on_intro_state()`, `_on_monologue_state()`, тощо) запускали діалоги без перевірки, чи вони вже були прочитані. Це призводило до:
- Повторного запуску діалогів при поверненні до сцени
- Погіршення ігрового досвіду
- Можливих проблем з прогресом (якщо діалоги встановлюють quest flags)

## Виправлення

### 1. Додано функцію `_is_dialogue_completed()`

**Файл:** `SampleProject/Scripts/Gameplay/Scenes/Canyon.gd`

Функція перевіряє, чи діалог вже був прочитаний двома способами:

1. **Quest Flags (пріоритетний спосіб)**:
   - Перевіряє quest flags, пов'язані з діалогами
   - Мапінг діалогів на quest flags:
     - `Canyon_Intro` → `canyon_intro_complete`
     - `Canyon_StartMonologue` → `canyon_intro_complete`
     - `Canyon_Exploration` → `canyon_exploration_complete`
     - `Canyon_AbductionCutscene` → `canyon_abduction_complete`
     - `RoadToVillage` → `village_abduction_complete`
     - `Canyon_ExitCutscene` → `canyon_exit_cutscene_complete` (якщо додано)

2. **SaveSystem (резервний спосіб)**:
   - Перевіряє `completed_dialogues` в `SaveSystem.player_data`
   - Підтримує різні формати ID (з шляхом, без шляху, з розширенням, без розширення)

### 2. Додано перевірки в функції стану

У всіх функціях стану, які запускають діалоги, додано перевірку перед запуском:

- `_on_intro_state()` - перевіряє `Canyon_Intro`
- `_on_monologue_state()` - перевіряє `Canyon_StartMonologue`
- `_on_abduction_cutscene_state()` - перевіряє `Canyon_AbductionCutscene`
- `_on_exit_cutscene_state()` - перевіряє `Canyon_ExitCutscene`

### 3. Додано перевірку в `_execute_step()`

Функція `_execute_step()` тепер перевіряє, чи діалог вже був прочитаний перед запуском. Якщо діалог вже прочитаний, він пропускається з логуванням.

## Логіка перевірки

```gdscript
func _is_dialogue_completed(dialogue_id: String) -> bool:
    # 1. Нормалізуємо ID (видаляємо шлях та розширення)
    # 2. Перевіряємо quest flags (найнадійніший спосіб)
    # 3. Перевіряємо SaveSystem (якщо quest flags не знайдені)
    # 4. Повертаємо true, якщо діалог знайдено в будь-якому джерелі
```

## Переваги

1. **Покращений ігровий досвід**: Гравець не змушений повторно читати діалоги
2. **Коректний прогрес**: Діалоги не запускаються повторно, що запобігає проблемам з quest flags
3. **Гнучкість**: Підтримка двох джерел даних (quest flags та SaveSystem)
4. **Детальне логування**: Всі перевірки логуються для діагностики

## Діалоги, які перевіряються

- `Canyon_Intro` - вступний діалог
- `Canyon_StartMonologue` - монолог про діда та шамана
- `Canyon_Exploration` - діалог дослідження (запускається через тригер)
- `Canyon_AbductionCutscene` - катсцена викрадення
- `RoadToVillage` - діалог перед переходом до Village (вже має перевірку в `_on_to_village_state()`)
- `Canyon_ExitCutscene` - катсцена спуску з каньону

## Примітки

1. **Діалог `Canyon_Exploration`**: Цей діалог запускається через тригер, тому перевірка в `_on_exploration_state()` не потрібна, але вона є в `_execute_step()`.

2. **Діалог `RoadToVillage`**: Вже має перевірку в `_on_to_village_state()` через `village_abduction_complete`, тому додаткова перевірка не потрібна.

3. **Quest Flags**: Якщо потрібно додати новий діалог, додайте його в мапінг `dialogue_to_flag` в функції `_is_dialogue_completed()`.

## Перевірка

Після виправлень перевірте:

1. ✅ При поверненні до Canyon діалоги не запускаються повторно
2. ✅ Quest flags правильно відстежують завершені діалоги
3. ✅ Логування показує, коли діалоги пропускаються
4. ✅ Гравець може продовжити гру без повторного читання діалогів

## Діагностика

Якщо діалоги все ще повторюються, перевірте консоль на повідомлення:

- "🏜️ Canyon: ✅ Діалог X вже прочитаний (quest flag: Y)" - діалог правильно виявлений як прочитаний
- "🏜️ Canyon: ⏭️ Діалог X вже був прочитаний, пропускаємо" - діалог пропущено
- "🏜️ Canyon: 💬 ДІЯ: Запуск діалогу X" - діалог запускається (якщо не повинен, перевірте quest flags)

Якщо діалог не виявлений як прочитаний, перевірте:
1. Чи встановлюється quest flag після завершення діалогу
2. Чи правильно названий діалог в мапінгу `dialogue_to_flag`
3. Чи зберігається прогрес в SaveSystem
